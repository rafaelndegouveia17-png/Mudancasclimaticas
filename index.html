Para onde vai cada resíduo

As cores abaixo seguem o padrão de coleta seletiva usado no Brasil (Resolução CONAMA 275). O app destaca automaticamente a categoria correspondente a cada objeto detectado — mas essa aba funciona como referência mesmo sem a câmera.

O planeta e o seu lixo

Cada categoria de resíduo tem um destino — e um tempo de impacto muito diferente na natureza quando descartada errado. Arraste para girar o planeta.

Lixo nos oceanos

Boa parte do plástico descartado errado acaba levado por rios até o mar, onde correntes marítimas concentram os fragmentos em grandes manchas flutuantes — as chamadas ilhas de lixo. Arraste para explorar o globo.

Os pontinhos representam fragmentos de plástico acumulados pelas correntes oceânicas em zonas de convergência. Diferente de resíduo orgânico, o plástico não desaparece: ele se quebra em pedaços cada vez menores — os microplásticos — que permanecem na água e entram na cadeia alimentar marinha.

Boas práticas

    Sobre o projeto

    Este projeto usa um modelo YOLOv8 (exportado para ONNX) para detectar, pela câmera, objetos descartados em tempo real — desenhando uma caixa ao redor de cada item e indicando em qual lixeira ele deve ir. Diferente de um classificador simples, o YOLO consegue localizar e reconhecer vários objetos ao mesmo tempo em um único frame.

    Como funciona

    • A câmera captura frames de vídeo continuamente (sem precisar apertar botão).
    • Cada frame é redimensionado (letterbox) e enviado ao modelo .onnx carregado de ./modelo/best.onnx.
    • O ONNX Runtime Web roda a inferência direto no navegador (WebAssembly) — nenhuma imagem sai do seu dispositivo.
    • As caixas com maior confiança passam por supressão de não-máximos (NMS) e são desenhadas sobre o vídeo.

    Tecnologias usadas

    YOLOv8 (Ultralytics) ONNX Runtime Web HTML / CSS / JS puro getUserMedia API

    Como personalizar

    Exporte seu modelo treinado com yolo export model=best.pt format=onnx e coloque o arquivo em ./modelo/best.onnx. Depois, edite o array CLASS_NAMES no código-fonte com os nomes das classes na mesma ordem usada no treino (arquivo data.yaml), e ajuste o CLASS_MAP para ligar cada classe à categoria de descarte correta.
